# ORI-75 — Band independent review and joint test matrix

Date: 2026-10-02
Scope: `band/**` read-only review; no implementation defect reproduced.

## Review result

The current source matches the agreed W0 envelope and keeps the projection read-only. The transport restores the durable cache guard before loading a snapshot, refuses snapshot input until guard loading finishes, and remains closed after a guard read error. A complete transfer is checked against scope and revision before storage; ACK follows successful `storage.set`, exact string readback, in-memory acceptance, and is sent only for the matching transfer/revision. Scope changes increment generation, clear the projection, queue guard persistence and snapshot deletion behind active writes, and prevent late writes from being accepted or ACKed. Page selection is only a local preview. Ping/Pong is correlated, and pending Ping timers are cleared on response, send failure, or app destruction.

The leader's two startup-guard regressions are present and pass: `startup rejects snapshots until durable revocation guard is restored` and `guard read failure blocks snapshots while missing guard preserves legacy W0`. Other checked cases cover revoked/corrupt guard, delayed write followed by scope change, exact ACK eligibility, late revision, detail removal after a new snapshot/revocation, invalid/unmatched Pong, UTF-8 multipart reassembly, and transfer expiry. `npm test` from `band/vela` passed **19/19** on this source.

No issue requiring a source patch was reproduced. Missing `system.interconnect` and/or `system.storage` does not prevent app initialization; unavailable storage disables ACK eligibility and cache restore fails closed. App destruction detaches interconnect listeners, disposes fragment TTL timers and clears Ping timers. The local harness verifies these code paths, but a Xiaomi runtime/hardware run was not available in this review.

## Trust boundary and interface gap

`store.setScope()` is deliberately only a hook. No authenticated companion-session transition source currently calls it. A raw snapshot `scope` is checked against a verified expected scope when one exists, but the snapshot itself never authenticates or establishes that scope. The current projection remains read-only and labels session/hardware acceptance as pending. Do not treat a Pong, transport connection, or a scoped snapshot as proof of Orialis account, companion session, or target identity.

The phone-to-band contract remains existing `orialis.wear.v1`; this review does not introduce a new RPC, frame, or schema. Band expects the trusted phone adapter to call `setScope({accountId, sessionId, targetId?})` on authenticated session establishment and every account/session/target transition, and `setScope(null)` before logout, disconnect, or revocation takes effect. A transition must invalidate the previous scope even if a new handshake fails. Old-session messages must be stopped/rejected by phone and band; there must be no automatic replay after reconnection.

## Interface decisions for joint run

1. Keep W0 frames and `snapshot.ack {transferId, revision}` unchanged; ACK means durable client cache readback only.
2. Phone is the sole source of trusted account/session/selected-target transitions. The band must not accept raw snapshot scope as a handshake.
3. Keep identity transition handling explicit for target changes as well as login/logout. A failed new handshake leaves the previous scope revoked/cleared.
4. Phone `send`/delivery, Pong, durable band ACK, and business completion are separate outcomes. No remote operation is enabled by any of them.
5. Joint real-device acceptance is still pending: authorized SDK adapter, matching APK/RPK signer, pairing/permissions, actual session notifications, visible Ping/Pong, Chinese/emoji snapshot persistence after restart, and Bluetooth/Mi Fitness/locked-background recovery.
