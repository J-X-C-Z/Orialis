# Android 原生日历双向同步

来源：用户要求增加与手机原生日历的双向同步能力（2026-10-31）。

决策：通过 Android Calendar Provider 与用户显式选择的一个可写日历合并；权限只在设置中连接时请求。Dart 复用 EventRepository，因此导入和修改继续进入现有云同步 outbox。映射和三方比较基线按 Orialis 账户数据库名、系统日历分别持久化。以系统事件ID及 Orialis UUID marker 去重；导入采用稳定UUID，避免进度写入中断产生副本。

新增、修改、删除双向传播。两侧均修改时保留系统侧冲突副本再发布本地版本；删除与修改冲突也保留变更。读取失败不作为空快照；权限撤销、日历不可写或被移除时停止本轮并显示错误。停止连接保留两侧日程和映射。主应用运行时监听本地日程变化、每30秒检查系统变化并在resumed检查；未承诺杀进程后的后台同步。

当前工程没有 iOS target，本次实现 Android。Orialis 没有重复规则模型，系统重复/例外日程标记并跳过，避免把系列变成单次事件。原生多个提醒在Orialis表示为一个最早提醒，Orialis写回使用该单提醒模型。

入口：个人/系统设置 → 手机日历双向同步 → 连接系统日历。合并范围为所选日历中可表示的全部单次日程，不自动读取其他日历。

验收：Android Kotlin定向编译成功；7项新双向同步测试和5项现有日程动作/离线入口测试，共12项通过；定向 Flutter analyze 和 git diff --check 通过。使用内存数据库和模拟平台通道，未安装手机、未读写真实用户日历；Provider/OEM兼容性、真实权限界面、端到端云同步尚待实机验收。未提交或发布。
