# Orialis 1.1.0

本次整合屏幕记忆与聊天协作的新功能，并保留此前1.0.x的消息提速、通知、主题、智能回复和Hermes路由改进。

## 新功能

- **按需辅助截屏**：Android11及以上手动开启一次“Orialis 辅助截屏”后，快捷键无需每次请求录屏授权。未开启时保留系统确认。只响应用户主动点击，不持续记录屏幕。
- **保存后停留原应用**：快捷截屏、分享到记忆后反馈保存成功，不再自动打开Orialis界面。
- **无界面后台理解**：截图和分享内容保存后由系统安排后台分析，复用现有账号与记忆接口。任务结束释放后台引擎；实际时机受联网、省电和系统任务额度影响。
- **标题与UP主匹配视频**：没有原链接/BV号时，可依据同一B站视频的可见标题和UP主查找唯一候选并复核，再获取字幕或抽样画面。无法唯一匹配时保留截图并提示补充原链接，不猜测其他平台视频。
- **并行回应与自然进度**：首回应与正文并行，长任务可结合真实公开阶段生成中途摘要。辅助生成超时、过时或不可用时跳过，不阻塞最终回复；最终回复之后不再补发进度。中途摘要只在聊天中展示，不反复弹系统通知，初始和最终回复通知保持。
- **可选Windows自动化源码**：提供Hermes收件箱水位读取与待办摘要工具及测试，不默认创建计划任务或发送消息。

## 修复与验证

修复了前台重试与后台任务竞争时，旧任务重新认领并覆盖较新记忆结果的问题；任务认领和结果提交均比较当前任务身份。手机完整回归540项通过、2项按既有条件跳过，新增8项认领/空ID回归已覆盖；正式Android arm64构建与静态检查通过。最后的摘要通知过滤另有18项通知/系统回归通过，另有4项中英旧状态条/历史记录回归通过，未在这些局部补丁后重复全量。公开Python合同/接口检查、Windows工具8项mock测试、记忆后台51项测试通过。

## 使用与验收边界

免重复确认需在“记忆 → 截屏设置”进入系统设置，手动开启“Orialis 辅助截屏”。没有自动批准系统权限。具体ROM的控制中心收起、截屏授权与冷进程JobScheduler链路尚未逐项真机验收；已确认服务/权限声明与后台入口保留在正式包，手机覆盖安装与启动检查通过。

自然进度摘要按辅助模型可用性尽力生成。Azure/Hakari已有不同主题的真实摘要；Windows在先前8秒预算下的长任务辅助请求超时，按设计跳过，最终回复、顺序和幂等检查正常；后续12秒预算候选的106项插件测试通过，仍不以单元测试冒充四机长任务摘要全部验收。不能将此记为“四设备自然摘要长任务全部通过”，也不承诺每个任务必有中途摘要。B站理解使用真实字幕或抽样画面，不承诺任意视频全内容无遗漏理解。
