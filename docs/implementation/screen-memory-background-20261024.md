2026-10-25更新：本文保留上一轮验收快照；其中剩余测试问题已修复，分类与视频功能及新验收结果见 [后续交付记录](screen-memory-classification-video-20261025.md)。

来源：用户本轮要求移除添加快捷按钮区块、取消双层容器、将屏幕记忆处理与聊天分开；当前源码和自动化测试。

## 验收结果

- 记忆列表移除整块快捷按钮引导及相关页面回调；记录使用 `LuminaListRow` 自带的单个 `LuminaSurface`。
- 手机通过独立的 `/api/v1/memory/analyses/{id}` 提交和查询分析；不创建聊天、不发消息、不轮询聊天记录。
- Azure Hermes 通过独立 `memory.analyze` / `memory.result` 通道完成一次无工具模型调用。任务在服务器继续运行，手机恢复后取回结果。
- 保留原始截图、分享内容、完整来源链接和笔记；账号切换或页面任务取消后不回写旧账号结果。
- 同一账号、同一记忆的重复提交复用任务；失败可重试。服务器重启中断的任务会过期，旧执行结果不能覆盖新一次结果。
- 旧版已经生成的聊天和历史字段保留；新流程不再使用这些聊天标识。

## ADR：屏幕记忆独立于会话

决定：新增专用后台分析接口和持久化结果表，不用隐藏聊天承载后台工作。截图以已有压缩副本内联提交；服务器只持久化证据指纹和分析结果，不保存原始提示或截图。

原因：记忆收藏和聊天具有不同的交互及历史语义。隐藏会话仍会创建消息数据，并继承聊天的回执、状态和回复处理。独立通道直接表达后台任务的运行和结果。

影响：上线须同时更新服务器（执行迁移 `0019_memory_analyses.sql`）、Azure Hermes 插件和手机客户端。缺少新能力时显示失败，保留原始记忆，不回退到发消息。部署和真实模型往返尚未进行。

协议与限额见 [memory-analysis-v1.md](../../protocol/agent-gateway/memory-analysis-v1.md)。
