# Orialis 按任务内容生成自然中途摘要（2026-10-25，验收草稿）

TASK-022 将 TASK-021 的本地阶段模板替换为结合本次任务和公开执行事实生成的自然摘要。源码已实现，摘要模块单元测试通过，当前完整插件目标测试日志显示 106 项通过；实际部署与四台运行验收由主执行 Agent 整合。本文目前不表示四台已上线或已通过真实验收。

## 行为与上下文

普通消息仍保持自然首回应与主处理并行，完整回复优先。长任务没有公开输出达到约 30 秒时，独立后台摘要协程读取一个有界快照：本次用户请求的前 4000 字、最多 10 个附件名称、当前 processing/tool/returned 阶段及公开工具类别、最近 6 次阶段变化、最近 3 条主模型公开中间说明和最近 3 条已生成进度。不会将普通聊天全文、原始工具参数/结果或隐藏思考作为摘要输入。

主模型公开说明来自既有 `_interim_send` 路径。阶段事实只能说明当前正在处理什么、工具仍在运行或调用已返回；返回不等于成功，无法据此声称已修复、找到资料、验证通过或已经读取附件。系统提示要求摘要至少点明本次请求的具体对象或目标，在有证据时概括已知进展或下一步，不只泛泛说“仍在处理中”，也不复述用户要求的最终输出标记。

这与“读取主模型内部思考后再总结”不同：摘要只使用本来就允许公开的内容和实际状态。没有已知结果时自然说明当前任务与等待阶段，不编造结论。Hermes 自己产生的原生 Commentary 保持既有路径，可直接向用户说明有实质内容的进展。

## 后台调度与优先级

`TurnUpdates` 在原有后台 pump 中调用摘要，不增加主处理的 await。每轮以 `_reporting` 防止摘要生成协程重入，相邻尝试至少间隔 30 秒；已成功汇报的同一 revision 不重复。阶段变化增加 revision；摘要生成前保存快照，返回后重新核对 revision、paused 和 closed，过时结果直接丢弃。

新摘要复用已配置的 `orialis_initial_response` 辅助路由，不修改四台主模型配置或正文 low 档位。调用显式发送 `thinking=false` 与 `enable_thinking=false`，输出预算 180 tokens，等待预算 12 秒；同步 SDK 调用通过 `asyncio.to_thread` 移出网关事件循环。正文或原生公开输出会暂停并取消后台汇报，新工具阶段可恢复；最终完成、停止、断线或新轮开始会关闭旧轮更新。

失败、限流、超时、空内容、字面空串、超长文本或包含 reasoning 内容/正数 reasoning_tokens 的响应均跳过。中途摘要不再降级成固定模板；首回应原有故障备用短句不属于此次修改范围。SDK 的底层线程或网络请求可能在协程取消后才结束，但迟到结果不写摘要缓存，也不应发送到已结束或已经变更的任务。

“非阻塞”指主处理和最终投递不串行等待新增后台摘要生成或其 ACK，不等于承诺额外模型请求没有任何资源开销。后台摘要仍消耗辅助模型容量，模型服务和网络的实际耗时可能波动。原生 Commentary 沿用 Hermes 既有投递机制，本次不更改其内部发送队列。

## 缓存与范围

`progress_response.py` 将完整有界快照的 SHA256 作为私有缓存文件名，仅保存输入摘要、公开摘要、模型名和非思考使用量，不保存完整请求、阶段原文输入或思考内容。文件写入为 0600 并原子替换，沿用既有附件缓存的身份隔离与保留期。同一份事实快照重试复用已生成文字，事实或本次请求改变时使用不同缓存身份。既有消息 ID 与原用户 anchor 关联保持，不新增协议或数据库字段。

当前用户显式要求中途汇报结合处理内容自然生成，因此取代 `tasks/done/TASK-021-progress-replies.json` 中的“No additional model requests for periodic progress; no core or schema changes”约束中的前半句，仅允许为此新增后台辅助调用。保留不改 Hermes core、主模型、客户端和数据库结构的边界，以及此前并行首回应、完成顺序与系统通知优先级修复。实现范围为 `progress_response.py`、`turn_updates.py`、`adapter.py`、对应测试及说明文档；其余正在进行的记忆/视频修改不在此次范围。
