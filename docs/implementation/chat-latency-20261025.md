## 已确认的问题与改动

发送原本先确认会话绑定，再调用整轮同步。即使消息已经上传，界面仍会等所有会话历史、任务、日历和项目处理完成；在已有同步运行时，还可能等待整个旧轮次。现在发送只等待本会话截至目标消息的必要待发消息、会话变更、附件及消息 POST，服务器确认后即可结束发送状态。其他会话的历史和附件不阻塞当前发送；后台同步继续按原先顺序执行。

后台同步与定向发送共享会话/消息的在途请求，并在执行前重读当前本地记录，避免陈旧待发列表重复上传。保留同会话前序消息及引用顺序、固定 ID 重试、附件身份和错误恢复。协调器释放时等待定向发送，保护账号切换。桌面关闭后台聊天同步时，显式发送仍可用。

设备查询、会话绑定和命令请求复用当前登录身份的 HTTP 客户端；身份变化时释放旧客户端。登录、权限和发送前的权威绑定校验仍保留。

回到应用前台会立即尝试连接已断开的实时通道，并取消正在等待的后台重连计时；已有健康连接继续使用。原先已断开的客户端可能等最多32秒的重试间隔。收信继续通过实时通道直接入库。

网页消息 POST 成功后立即解锁发送，历史刷新在后台进行；等待助手回复时每1秒刷新，收到回复后恢复5秒间隔。保留请求合并、隐藏页面暂停、卸载清理、滚动位置、草稿与幂等重试。

## 线上诊断边界

Aozora 本机健康接口三次200，中位约1.15ms；认证设备接口三次200，中位约3.10ms。它们衡量本机API处理，不能代表手机公网往返。Mac 上同一连接的连续健康请求观测约0.42秒，新连接一次约1.15秒；环境经过本机代理，仅作为连接建立开销样本，不能作为手机提速比例。

最近20组现存消息从服务器提问入库到关联完整回复的时间，按设备中位数分别约Azure104秒、Hakari21秒、Mac9秒、Windows1.4秒。样本量分别6/10/1/3，内容和工作量不一致，且包含模型生成与工具执行，不能用于设备性能排名或纯传输延迟判断。本轮未发送新的实际模型对话，未量化更新前后真机完整往返速度，未承诺模型回答时间。

Paperclip桥接有旧事件积压，但其网络重试在后台线程，没有证据将其判定为所有设备聊天慢的直接原因；未改动该独立服务。
