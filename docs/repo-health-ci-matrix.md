## Workflow events and path routing

The workflow must run on pushes to `main`, `refactor/repository-health-20261004`, its child refs, and `health-20261004/**`, and on pull requests. Package jobs are gated by package source plus its lockfile. Shared `protocol/contracts/**` changes run Rust, Python contract/Hermes/SDK, mobile/macOS, and Vela consumers. `Cargo.lock` selects Rust; `mobile/pubspec.yaml` and `mobile/pubspec.lock` select mobile/macOS; `packages/lumina_ui/**` selects mobile/macOS/library/showcase; `packages/lumina_tokens/**` selects all Flutter and Web consumers. Root roadmap black-box tests select both Python and Rust: Rust starts a loopback service with a disposable SQLite database and runs the full test suite; no configured API or production target is used. Workflow or selector changes run all component checks. The selector processes both `push` and `pull_request` ranges and exits 2 for missing or malformed event data, missing commit objects, unsupported events, or a missing output target.

## First-push hygiene baseline follow-up

The first push to a new task branch uses an all-zero `before` SHA. The hygiene job still runs `git diff --check` against the empty tree so pre-existing whitespace errors are found and corrected. The initial run found extra blank EOF lines in `Cargo.toml`, `docs/fangcun-migration.md`, `packages/lumina_ui/.gitignore`, `packages/lumina_ui/analysis_options.yaml`, and `packages/lumina_ui/pubspec.yaml`; one extra final newline was removed from each. The artifact checker has different semantics: it checks *new* paths/blobs, so on a first push its baseline is the merge base with `origin/refactor/repository-health-20261004`, the authorized integration target. This keeps existing large assets out of the new-blob check while still checking every change from the integration baseline to the pushed head. If that target or merge base is unavailable, the job fails closed. Pull requests continue to check the full base/head range; ordinary pushes continue to check before/after.
